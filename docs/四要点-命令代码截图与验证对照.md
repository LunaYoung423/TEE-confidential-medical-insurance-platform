# 赛题四要点：对应代码/命令、如何截图、如何判定通过

下表按你的四个要求逐条对应**仓库内脚本、指令、截图建议、验证标准**。默认在 Linux/阿里云 ECS、项目根目录 `confidential-computing-platform/` 下操作。

**需要「一个点一个点」按步骤执行时，请用：** [`四要点分步测试操作手册.md`](./四要点分步测试操作手册.md)。

## 要点（1）数据在 TEE 外始终为密文

| 子项 | 对应代码/命令 | 如何截图（建议） | 如何验证（通过标准） |
|------|----------------|------------------|----------------------|
| 自动化检查密文不可当明文用 | **脚本**：`scripts/verify_ciphertext_and_attack_simulation.py` | 终端全屏：`python3.8 scripts/verify_ciphertext_and_attack_simulation.py --plain data/train_claims_numeric.csv` 从命令行到最后一行输出 | 输出含「宿主机直接 pandas.read_csv(密文) 是否成功: **False**」；末尾有「自检项完成」类成功提示；无 Traceback |
| 有真实密文文件时 | 同上，加参数：`--cipher data/encrypted_train_data.bin`；若有 DEK 再加 `--key-hex <32位hex>` | 同上；可再开一窗显示 `ls -lh data/encrypted_train_data.bin` | 无密钥时：直接读密文失败；有 `--key-hex` 且匹配时：不应出现「解密结果与明文不一致」警告 |
| 端到端产生密文（与项目一致） | **代码路径**：`scripts/integrated_client.py` → `encrypt_data_file`（SM4）；训练读 `file://...encrypted_train_data.bin` | **宿主机**执行：须带 `export KEEP_ENCRYPTED_TRAIN_BIN=1`，再 `python3.8 scripts/integrated_client.py`（未设置则成功后脚本会删密文）。容器内需 host 网：Compose v2 见《分步手册》1-C **备选一**；若 `unknown flag: --network` 用 **备选二** `docker run --network host`。截图含「数据加密完成」与 `ls -lh ./data/encrypted_train_data.bin` | 磁盘存在 `.bin` 密文；日志显示训练使用的 `data_uri` 指向密文路径；**勿**在默认 bridge 的 `cc-client` 内直接跑（`localhost` 端口不可达） |
| 明文≠密文（哈希） | **指令**：`sha256sum data/train_claims_numeric.csv data/encrypted_train_data.bin` | 终端两行哈希并排可见 | 两个 SHA-256 **完全不同** |
| 密文形态 | **指令**：`file data/encrypted_train_data.bin`；`xxd data/encrypted_train_data.bin \| head` | 各一屏截图 | `file` 显示为 data/binary 类而非 UTF-8 text；`xxd` 为无明显可读 ASCII 病历内容 |

**核心对应文件（答辩可引用）**  
- 客户端加密：`scripts/integrated_client.py`（`encrypt_data_file`）  
- 容器内解密训练：`module2/main.py`（`crypto.decrypt_data` → `load_data_from_bytes`）

## 要点（2）模拟攻击测试（宿主机侧内存嗅探 / 冷启动 — 演示级）

| 子项 | 对应代码/命令 | 如何截图（建议） | 如何验证（通过标准） |
|------|----------------|------------------|----------------------|
| 「嗅探」磁盘密文 | **脚本**：`verify_ciphertext_and_attack_simulation.py`（同上） | 截图中含「pandas.read_csv(密文) 是否成功: False」 | 攻击者把密文当 CSV 解析 **失败** |
| 错误密钥 | **脚本内部**：用错误 SM4 密钥解密后 `_is_valid_claims_like_csv` | 截图中含「错误密钥解密后是否为合法 CSV: **False**」 | 无正确密钥无法得到可用训练表 |
| 表头明文是否进密文 | **脚本**：扫描首行 CSV 列名是否在密文字节中 | 截图「表头 token 在密文中是否出现: **未发现**…」 | 常见列名不以 UTF-8 子串出现在密文中 |
| 人工辅助 | **指令**：`strings data/encrypted_train_data.bin \| head -50`（可选） | 截图 strings 输出 | 不应出现完整可读病历行（与业务字段一致的长串） |
| 内存/冷启动（叙述） | **无单独脚本**：文档 + 环境说明 | PPT/文档页：说明海光 CSV 下内存加密；或截图 `curl .../api/v1/health` 中 `csv_device: true` | 通用 ECS 写「设计目标 + 磁盘侧已验证」；**海光机**写「硬件隔离 + 本项磁盘攻击无效」 |

**说明**：真实冷启动/DRAM 转储需特定实验环境；比赛材料以 **磁盘密文 + 错误密钥 + 不可解析** 为主证据，硬件保护用环境与文档佐证。

## 要点（3）分析结果与明文计算一致

| 子项 | 对应代码/命令 | 如何截图（建议） | 如何验证（通过标准） |
|------|----------------|------------------|----------------------|
| 算法路径一致性（推荐主证据） | **脚本**：`scripts/performance_benchmark.py` | 终端：`python3.8 scripts/performance_benchmark.py --train data/train_claims_numeric.csv --val data/val_claims_numeric.csv --algorithm xgboost_classifier --runs 5 --json-out reports/benchmark.json`，截完整 JSON 输出 | `accuracy_abs_diff` 为 **0** 或极小（如 <1e-6）；若有 AUC，`auc_abs_diff` 同为 0 或极小 |
| JSON 文件留档 | 同上 `--json-out` | 用编辑器打开 `reports/benchmark.json` 截图，圈出 `metrics_plain`、`metrics_crypto_pipeline`、`accuracy_abs_diff` | 两路 `accuracy`（及 AUC）**一致** |
| 端到端解密模型 | **脚本**：`scripts/evaluate_claims_model.py` | 截图：`python3.8 scripts/evaluate_claims_model.py --model model_xxx.pkl --val data/val_claims_numeric.csv` 的准确率/AUC/分类报告 | 与 `benchmark.json` 里 `metrics_plain` **同一数量级且一致**（验证集极小时允许微小浮动，建议增大验证集） |

**核心对应文件**  
- 对比逻辑：`scripts/performance_benchmark.py`（明文训练 vs SM4 包壳后同字节训练）  
- 评估：`scripts/evaluate_claims_model.py`

## 要点（4）密态相对明文损耗 ≤20%

| 子项 | 对应代码/命令 | 如何截图（建议） | 如何验证（通过标准） |
|------|----------------|------------------|----------------------|
| 层 A：训练 vs 训练+国密包壳 | **脚本**：`performance_benchmark.py`（同上） | 截图 JSON 中：`median_plain_train_seconds`、`median_crypto_pipeline_seconds`、`overhead_percent_vs_plain_train` | 若 `overhead_percent_vs_plain_train` **≤20**：直接写「满足层 A」；若 **>20**：在文档说明「样本小、纯训练极短导致加密占比高」，并补充层 B 或调大 `n_estimators` 重测 |
| 层 B：端到端 wall time | **指令**：宿主机 `/usr/bin/time -f "wall_sec=%e" python3.8 scripts/integrated_client.py`；或 `docker compose run --rm --network host ...`（见《分步手册》4-B） | 截图多次运行终端，或汇总表（Excel/文档） | 自建「明文基线」同机同资源跑 5 次以上，取**中位数**算损耗%；≤20 为理想，否则报告写明口径与优化 |

**调大训练占比（可选，便于压损耗%）**  
- 编辑 `performance_benchmark.py` 内默认 `params` 或给脚本加参数（若需可后续扩展）；临时可在脚本里把 `n_estimators` 改为 200 再跑，截图新的 `overhead_percent_vs_plain_train`。

**核心对应文件**  
- `scripts/performance_benchmark.py`（层 A 数值来源）

## 一条命令快速自检（开发用）

```bash
cd /path/to/confidential-computing-platform
python3.8 scripts/verify_ciphertext_and_attack_simulation.py --plain data/train_claims_numeric.csv
python3.8 scripts/performance_benchmark.py \
  --train data/train_claims_numeric.csv \
  --val data/val_claims_numeric.csv \
  --runs 5 \
  --json-out reports/benchmark.json
```
