# 四要点分步测试操作手册（逐点独立完成）

按「一次只测一个要点」组织。除**全局准备**外，各要点可单独执行。项目根目录均指 `confidential-computing-platform/`。

---

## 与当前代码的适配说明（必读）

1. **端到端客户端 `integrated_client.py`**：控制器返回的证明/训练地址为 **`localhost:宿主机随机端口`**。在默认 **bridge 网络** 的 `cc-client` 容器内，`localhost` 指向容器自身，**无法**连到动态训练容器。因此 **1-C、4-B** 中与 `integrated_client` 相关的步骤优先在 **ECS 宿主机**用 **`python3.8 scripts/integrated_client.py`** 执行；若必须在容器内跑，需 **host 网络**：Compose v2 可用 **`docker compose run --rm --network host`**（并设置 `CONTROLLER_URL=http://127.0.0.1:8080`、`VERIFY_URL=http://127.0.0.1:8081`）；若报 **`unknown flag: --network`**，请升级 Compose v2 或改用 **1-C「备选二」** 的 **`docker run --network host`**（与 `client` 服务同等卷挂载）。
2. **数据路径**：在宿主机项目根下运行时，脚本会默认使用 **`./data/train_claims_numeric.csv`** 与 **`CLIENT_DATA_DIR=./data`**（若存在）；无需再手写 `/data/...`，除非你在容器内跑。
3. **真实 CSV 远程证明**：若环境具备 `/dev/csv-guest`，证明证据 `type` 应为 **`csv`**（非 `csv_simulated`）。材料中可增截「健康检查 / 证明响应」增强叙述（见 **G4**、要点 2-D）。

# 要点（1）数据在 TEE 外始终为密文

**目标**：证明持久化在磁盘/共享卷上的是**密文**，不能当明文 CSV 直接使用；且与明文文件在哈希与形态上不同。

## 1-A 仅用明文自动生成密文并检测（不依赖 Docker）

**步骤 1** 进入项目根（若新开终端）：

```bash
cd /path/to/confidential-computing-platform
```

**步骤 2** 运行密文形态自检脚本（内部会用随机密钥加密再测）：

```bash
python3.8 scripts/verify_ciphertext_and_attack_simulation.py \
  --plain data/train_claims_numeric.csv
```

**步骤 3** 对照输出逐项确认：

- 出现「宿主机直接 pandas.read_csv(密文) 是否成功: **False**」
- 「错误密钥解密后是否为合法 CSV: **False**」
- 末尾类似「自检项完成」

**截图**：从命令行到最后一行输出的**完整终端窗口**。

**验证通过**：无 Python 报错；上述两行均为 False。

---

## 1-B 哈希与文件类型（强化材料）

**步骤 1** 先得到一份密文文件。任选其一：

- **方式 i**：跑完 1-A 后，脚本若打印了「临时密钥」，可自己用同一密钥生成密文（见要点 2 或 integrated 流程）；或  
- **方式 ii**：完成下方 **1-C** 后使用 `data/encrypted_train_data.bin`。

**步骤 2**（在已有 `train_claims_numeric.csv` 与 `encrypted_train_data.bin` 时）执行：

```bash
sha256sum data/train_claims_numeric.csv data/encrypted_train_data.bin
file data/encrypted_train_data.bin
xxd data/encrypted_train_data.bin | head -n 8
```

**截图**：三条命令的输出各一屏，或合并一屏。

**验证通过**：

- 两个 SHA-256 **不相同**
- `file` 不是「UTF-8 Unicode text」类纯文本
- `xxd` 前若干行无整行可读中文病历

## 1-C 与系统一致的端到端密文落盘（依赖 Docker）

**步骤 1** 确保 G3 已执行，`docker compose ps` 正常。

**步骤 2** 在 **宿主机项目根** 跑工作流并**保留**密文（与当前控制器 `localhost:端口` 行为一致，**勿**在默认网络的 `cc-client` 内直接跑）：

```bash
cd /path/to/confidential-computing-platform
export KEEP_ENCRYPTED_TRAIN_BIN=1
export TRAIN_ALGORITHM=xgboost_classifier
# 可选：显式指定（与默认 ./data 一致时可省略）
# export TRAIN_DATA_PATH=/root/.../confidential-computing-platform/data/train_claims_numeric.csv
# export CLIENT_DATA_DIR=/root/.../confidential-computing-platform/data
python3.8 scripts/integrated_client.py
```

**重要（为何训练成功却找不到密文）**：`KEEP_ENCRYPTED_TRAIN_BIN` 必须在**启动客户端的同一轮执行前**已导出（`1` / `true` / `yes` 均可）。若未设置，脚本在 `finally` 中会**删除** `CLIENT_DATA_DIR/encrypted_train_data.bin`（设计为默认不落盘敏感密文）。需要 **1-B 截图**或留档时，务必带 `export KEEP_ENCRYPTED_TRAIN_BIN=1` **重新跑一遍**客户端。

**备选一（必须在容器内跑时）**：使用 **host 网络** 并指向宿主机上的控制器与证明服务：

```bash
cd /path/to/confidential-computing-platform
docker compose run --rm --network host \
  -e CONTROLLER_URL=http://127.0.0.1:8080 \
  -e VERIFY_URL=http://127.0.0.1:8081 \
  -e TRAIN_DATA_PATH=/data/train_claims_numeric.csv \
  -e CLIENT_DATA_DIR=/data \
  -e KEEP_ENCRYPTED_TRAIN_BIN=1 \
  -e TRAIN_ALGORITHM=xgboost_classifier \
  client python3 scripts/integrated_client.py
```

**备选二（`docker compose run` 报 `unknown flag: --network`）**：多为 Compose 过旧或非官方实现。请升级 **Docker Compose v2**（`docker compose version`），或用与 `docker-compose.yml` 中 **`client`** 相同的挂载，直接 **`docker run --network host`**（先构建并取镜像 ID）：

```bash
cd /path/to/confidential-computing-platform
docker compose build client
CID=$(docker compose images -q client)
# 若 CID 为空：执行 docker images，选用本项目的 *-client 镜像 ID 替换下面的 $CID
docker run --rm --network host \
  -v "$(pwd)/module1:/app/module1" \
  -v "$(pwd)/scripts:/app/scripts" \
  -v "$(pwd)/data:/data" \
  -v "$(pwd)/logs/client:/app/logs" \
  -w /app \
  -e CONTROLLER_URL=http://127.0.0.1:8080 \
  -e VERIFY_URL=http://127.0.0.1:8081 \
  -e TRAIN_DATA_PATH=/data/train_claims_numeric.csv \
  -e CLIENT_DATA_DIR=/data \
  -e KEEP_ENCRYPTED_TRAIN_BIN=1 \
  -e TRAIN_ALGORITHM=xgboost_classifier \
  "$CID" python3 scripts/integrated_client.py
```

**步骤 3** 在宿主机查看密文是否存在：

```bash
ls -lh data/encrypted_train_data.bin
```

**截图**：① `integrated_client` 终端中含「证明白名单已更新」或「远程证明通过」「数据加密完成」、保存路径；② **`ls -lh data/encrypted_train_data.bin`** 一行；③（可选）日志中含 **`"type": "csv"`** 的证明响应片段（真实 CSV 环境）。

**验证通过**：`data/encrypted_train_data.bin` 存在且为非零字节；日志表明训练使用的数据经加密写入该路径。

# 要点（4）密态相对明文计算效率损耗（≤20%）

**目标**：给出**可量化**的耗时对比；赛题常要求「相同算力」下密态相对明文 ≤20%，建议分两层写报告。

## 4-A 层 A：纯训练 vs「训练 + 国密加解密包壳」（不依赖 Docker）

**步骤 1**

```bash
cd /path/to/confidential-computing-platform
python3.8 scripts/performance_benchmark.py \
  --train data/train_claims_numeric.csv \
  --val data/val_claims_numeric.csv \
  --algorithm xgboost_classifier \
  --runs 5 \
  --json-out reports/benchmark.json
```

**步骤 2** 记录 `reports/benchmark.json` 中：

- `median_plain_train_seconds`  
- `median_crypto_pipeline_seconds`  
- `overhead_percent_vs_plain_train`

**截图**：含上述三个字段的 JSON（终端或文件）。

**验证通过**：

- 若 `overhead_percent_vs_plain_train` **≤ 20**：层 A 可直接写「满足 ≤20%」。  
- 若 **> 20**：在报告中如实填写数值，并说明「训练时间过短、加密固定开销占比高」；继续测 **4-B** 或增大 `n_estimators` 后重跑（见 4-C）。

## 4-B 层 B：端到端 wall time（依赖 Docker，正式报告建议有）

**步骤 1** 确保服务已启动，连续测 **至少 5 次**，每次在**宿主机项目根**执行（与 1-C 同理，避免 bridge 网络下 `localhost` 错误）：

```bash
cd /path/to/confidential-computing-platform
/usr/bin/time -f "wall_sec=%e" python3.8 scripts/integrated_client.py
```

**备选一（容器内 + host 网络，Compose v2）**：

```bash
/usr/bin/time -f "wall_sec=%e" docker compose run --rm --network host \
  -e CONTROLLER_URL=http://127.0.0.1:8080 \
  -e VERIFY_URL=http://127.0.0.1:8081 \
  -e TRAIN_DATA_PATH=/data/train_claims_numeric.csv \
  -e CLIENT_DATA_DIR=/data \
  client python3 scripts/integrated_client.py
```

**备选二**：与 **1-C 备选二**相同，将 `docker run ... python3 scripts/integrated_client.py` 整行前面加上 `/usr/bin/time -f "wall_sec=%e"` 即可。

**步骤 2** 在表格中记录每次 `wall_sec=...`，取**中位数** \(T_{\text{密态}}\)。

**步骤 3** 用**同一台 ECS、相同 CPU/内存限制**，运行你的「明文基线」（例如：同镜像内仅读明文 CSV、同算法训练、不含证明与 HTTP 的短脚本），同样测 5 次以上取中位数 \(T_{\text{明文}}\)。

**步骤 4** 计算：

\[
\text{损耗}\% = \frac{T_{\text{密态}} - T_{\text{明文}}}{T_{\text{明文}}} \times 100
\]

**截图**：5 次 `time` 原始输出 + 汇总表（Excel/文档均可）。

**验证通过**：损耗 ≤20% 为理想；否则在文档说明口径、环境与已做优化。
