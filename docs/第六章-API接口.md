# 第六章 API接口

## 6.1 接口设计原则

本章给出机密计算协同平台的接口规范，覆盖认证鉴权、可信验证、密钥管理、任务执行、监控审计五类能力。系统角色仅包含两类：**用户**与**管理员**。用户负责业务任务发起与结果获取，管理员负责资源管理、安全审计与策略维护。

接口设计遵循以下原则：第一，安全优先，所有请求通过 `HTTPS + JWT`，关键操作写入审计链；第二，统一抽象，屏蔽底层TEE差异，调用方仅面向标准API；第三，异步解耦，长耗时操作采用“提交即返回 + 状态轮询”；第四，可追溯，所有关键请求需携带 `request_id` 以支持全链路追踪。

## 6.3 核心接口说明

### 6.3.1 认证与会话

`API-01 获取访问令牌`：登录后返回短期访问令牌与角色信息，用于后续接口调用。  
`API-02 刷新访问令牌`：在会话不中断的前提下更新令牌，降低长期凭据泄露风险。

### 6.3.2 可信验证

`API-03 查询TEE能力清单`：管理员查询节点TEE版本、可用加密内存、算法支持矩阵。  
`API-04 发起远程证明挑战`：为当前任务生成一次性挑战值，防止重放。  
`API-05 提交证据并验证`：核验证据、度量值与镜像摘要，返回可信结论。  
`API-06 建立安全会话`：基于证明结果协商会话密钥，形成后续敏感数据下发通道。

### 6.3.3 密钥与数据

`API-07 申请数据密钥DEK`：按任务粒度发放一次性数据密钥。  
`API-08 向TEE注入密钥`：将密钥定向注入目标机密容器实例。  
`API-09 上传加密数据分片`：支持大文件分片上传、完整性校验、断点续传。  
`API-10 提交数据装载任务`：在TEE内完成解封、校验、装载，形成训练输入。

### 6.3.4 训练与导出

`API-11 创建密态训练任务`：提交算法、数据集、镜像摘要与资源规格。  
`API-12 查询任务状态`：返回任务阶段、进度、健康状态。  
`API-13 取消训练任务`：终止任务并销毁密钥上下文。  
`API-14 导出加密结果`：导出密文模型或报告，返回下载凭据与校验值。

### 6.3.5 监控与审计

`API-15 查询TEE资源监控`：查看CPU、内存、加密页、队列时延等指标。  
`API-16 查询安全审计日志`：按任务、操作人、时间范围查询关键安全事件。

## 6.4 异步调用机制

远程证明、密钥注入、数据装载、模型训练均属于长耗时流程。平台采用“同步受理 + 异步执行”模式：接口提交后立即返回任务ID，调用方通过状态接口轮询，或由平台回调业务系统。

统一任务状态为：`PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。写操作支持幂等键，避免网络重试导致重复任务。回调消息带签名与时间戳，确保来源可验和请求不可重放。

## 6.5 错误码与安全规范

接口返回体统一为：

```json
{
  "code": "0",
  "message": "ok",
  "requestId": "req-20260417-0001",
  "timestamp": "2026-04-17T16:30:00Z",
  "data": {}
}
```

关键错误码建议如下：`E40101`（令牌无效）、`E40310`（权限不足）、`E40920`（远程证明失败）、`E40921`（度量值不匹配）、`E42230`（数据完整性失败）、`E50041`（密钥注入失败）、`E50050`（训练执行异常）。

安全控制采取“认证、授权、传输、密钥、审计”五层防护。对远程证明失败、跨租户访问、权限变更、密钥调用异常等高风险事件，系统强制记录审计并触发告警。

---

## 6.6 典型调用流程

以医保理赔联合训练为例，完整链路如下：用户登录获取令牌，发起远程证明并完成证据校验；用户建立安全会话并申请DEK，随后将密钥注入TEE；用户上传密文数据并提交训练任务；调度器在可信环境内启动密态训练；用户轮询任务状态并导出加密结果；管理员最终查询审计日志完成验收。

本流程形成“可信验证 - 密钥闭环 - 密态训练 - 加密导出 - 审计追踪”完整闭环，满足比赛对端到端安全验证和可运维性的要求。
