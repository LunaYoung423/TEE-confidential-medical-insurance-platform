# TEE 机密容器高价值医保数据计算平台

基于**海光 CSV 机密计算（TEE）** 的医保数据密态训练平台：在远程证明确认环境可信后，完成任务级密钥注入与 SM4 密态训练，并通过国密审计链保证操作可追溯、不可篡改。

> GitHub：https://github.com/LunaYoung423/TEE-confidential-medical-insurance-platform

---

## 项目背景

医保理赔等数据具有高敏感、高合规要求。传统云上训练面临「数据出域即明文」「宿主机管理员可见内存」等风险。本平台将训练负载放入 **TEE 机密容器**，贯彻：

**先证后钥 → 密文进笼 → 笼内计算 → 密文出笼 → 全程可审计**

---

## 核心能力

| 能力 | 说明 |
|------|------|
| **远程证明** | 海光 CSV 硬件证明；HMAC-SM3 保报告完整性，SM2 验签保来源可信；镜像白名单准入 |
| **密钥管理** | 证明绑定 RSA 公钥；任务级 DEK 经 RSA-OAEP 信封注入；TEE 会话持钥，对外仅暴露 `key_id` |
| **密态训练** | SM4 保护训练数据与模型；支持 XGBoost、逻辑回归等；明文仅在 TEE 内存短暂出现 |
| **安全审计** | SM3 哈希链 + 平台审计 SM2 签名；支持验链，关键操作可追溯 |

---

## 端到端流程（简述）

```
创建机密容器（白名单）
    → 远程证明（挑战 / 采证 / 验签 / 公钥绑定）
    → 生成 DEK → SM4 加密数据 → RSA 注入 DEK（换 key_id）
    → 提交训练（密文路径 + key_id）
    → TEE 内 SM4 解密 → 训练 → SM4 加密模型
    → 返回密文模型；审计链全程留痕
```

**算法分工（面试常用）：**

- **SM2**：证明报告验签；审计日志签名（与芯片证明密钥分离）
- **SM3 / HMAC-SM3**：审计哈希链；证明报告完整性
- **SM4**：业务数据与模型加解密
- **RSA-OAEP**：仅用于将 DEK 安全投递进 TEE（数字信封）

## 系统架构（逻辑）

```
用户端 / 业务侧
    │
    ├─→ 控制器（编排、建容器、白名单门禁）
    ├─→ 证明服务（平台验证方：白名单、CSV 验签）
    │
    └─→ CSV 机密容器（TEE）
            ├─ 证明代理：采证、RSA/DEK 会话、SM4 加解密
            └─ 训练服务：凭 key_id 调代理，跑密态训练
```

- **证明代理**：出示证据、持有会话密钥  
- **证明服务**：独立校验证据（与 TEE 自证分离）  
- **训练服务**：与代理同实例协同，减少跨容器跳转

## 快速开始

### 环境要求

- Docker / Docker Compose  
- 正式硬件证明需海光 CSV 机密计算环境（`/dev/csv-guest`）  
- 本地联调可按文档开启模拟证明开关（**仅开发调试**）

### 启动（示例）

```bash
# 配置环境变量（参考 module3/env.example，勿将真实密钥提交入库）
cp module3/env.example .env   # 按需修改

docker compose up -d --build
```

常用端口（以 compose 为准）：

| 服务 | 端口 |
|------|------|

| 证明服务 | 8081 |

## 安全设计要点

1. **镜像白名单**：未登记镜像不可创建训练容器  
2. **公钥绑定**：用户端用 SHA-256 核对证明材料中的 RSA 公钥哈希  
3. **明文密钥不上网**：传输为 RSA 信封密文或 `key_id`；DEK 明文仅在用户端与 TEE 会话  
4. **最小暴露**：训练侧凭 `key_id` 用钥，不长期持有 DEK 明文  
5. **落盘密文**：训练数据与模型对外以 `.enc` 等密文形态存在  
6. **审计可验**：SM3 链防篡改，SM2 签防伪造
